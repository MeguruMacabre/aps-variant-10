# Описание модели

## Правила варианта 10

1. ИБ: каждый источник генерирует заявки независимо от завершения обслуживания предыдущих. Число источников задаётся параметром.
2. ИЗ2: интервал поступления источника i распределён равномерно на [a_i, b_i], 0 < a_i < b_i.
3. ПЗ1: время обслуживания прибором j имеет экспоненциальное распределение с интенсивностью μ_j > 0. Среднее время равно 1/μ_j.
4. Д1ОЗ3: запись на первое свободное место от начала буфера; сдвига нет.
5. Д1ОО2: при занятости всех приборов и полном буфере вытесняется ожидающая заявка с максимальным номером источника. Новая заявка занимает освободившееся место.
6. Д2Б5: фиксируются все находящиеся в буфере заявки самого приоритетного источника. Пока в буфере остаются ID этого пакета, выбираются только они. Новые заявки в пакет не добавляются. Когда в буфере не остаётся заявок текущего пакета, формируется следующий. Находящиеся на приборах заявки предыдущего пакета продолжают обслуживаться.
7. Д2П2: поиск свободного прибора начинается с указателя, идёт циклически; после назначения указатель переходит на следующий за выбранным прибор.
8. ОР1: сводные таблицы по источникам и приборам.
9. ОД1: календарь событий, буфер и текущее состояние приборов.

## Дополнительные правила

- Меньший номер источника означает более высокий приоритет.
- При равенстве минимального приоритета вытесняется самая старая заявка; при равных временах — заявка с меньшим порядковым номером.
- Внутри пакета сначала выбирается самая новая заявка; при равных временах — с большим порядковым номером.
- При вытеснении заявка удаляется и из остатка текущего пакета.
- Начатое обслуживание не прерывается.
- Свободные приборы не простаивают при непустом буфере. Перед размещением новой заявки модель распределяет ранее ожидающие заявки; если после этого буфер пуст и прибор свободен, новая заявка назначается напрямую. Решение о непосредственном обслуживании принимает диспетчер постановки, а выбор конкретного прибора и назначение делегирует диспетчеру выбора.
- При одинаковом времени сначала обрабатываются завершения, затем поступления. Среди завершений — по номеру прибора, среди поступлений — по номеру источника, далее по порядковому номеру события. После каждого события выполняется распределение.

## Алгоритм по особым событиям

Календарь хранит события поступления и завершения обслуживания. Модель извлекает ближайшее событие и устанавливает соответствующее модельное время. При назначении заявки на прибор рассчитывается время обслуживания и в календарь добавляется событие его завершения.

Продолжительность прогона ограничивается числом сгенерированных заявок. После достижения лимита новые поступления не планируются. Оставшиеся заявки обслуживаются до освобождения буфера и всех приборов.

## Параметры примера

| Параметр | Выбранное значение |
|---|---|
| Источники | 3 |
| Приборы | 2 |
| Буфер | 3 места |
| Интервалы каждого источника | Uniform(1, 10) |
| Интенсивность каждого прибора | μ = 0.25; среднее обслуживание 4 |
| Единица времени | Условная |

Параметры выбраны для демонстрационного примера. Суммарная интенсивность поступлений равна 3/5.5 ≈ 0.545, интенсивность обслуживания — 2 × 0.25 = 0.5. Расчётная нагрузка составляет примерно 1.091, поэтому возможно переполнение буфера.

## Результаты моделирования

В автоматическом режиме выводятся количество поступлений, вероятность отказа, среднее время в системе, ожидания и обслуживания, дисперсии времени ожидания и обслуживания по источникам, коэффициенты использования приборов. Требуемая относительная точность — 10%, доверительная вероятность — 0.9.
